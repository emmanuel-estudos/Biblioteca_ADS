# Conceitos Básicos

Nesse documento, serão apresentados **Conceitos Básicos** e principais **Terminologias** de Banco de Dados.

## Introdução

Diariamente, realizamos tarefas que envolvem alguma interação com bancos de dados:

- Ao realizar uma transação bancária;
- Ao reservar um hotel ou uma passagem;
- Ao acessar o catálogo de uma loja;

Muitos sistemas atuais envolvem o uso de um banco de dados.

Para entendermos os fundamentos da tecnologia de banco de dados, precisamos compreender primeiro alguns de seus conceitos básicos.

## Conceitos Básicos

### O que é um banco de dados?

#### Definição genérica

É uma coleção de dados relacionados e armazenados em algum dispositivo.

Podemos definir melhor um banco de dados com base em suas características.

#### Características

Um banco de dados representa algum aspecto do mundo real. Também chamado de minimundo ou universo de discurso. Mudanças no minimundo precisam ser refletidas para o banco de dados.

Um banco de dados é uma coleção de dados logicamente coerente. Os dados desta coleção possuem um significado inerente.

Um banco de dados é projetado, construído e populado com dados para uma finalidade específica, tendo grupo definido de usuários interessados em seu conteúdo.

Os bancos de dados atuais normalmente precisam gerenciar uma grande quantidade de dados. Isto requer o uso do computador para dar o suporte a esta tarefa.

Antigamente, os bancos de dados das aplicações eram implementados como um conjunto de arquivos. O programador tinha que implementar todas as rotinas responsáveis pelo gerenciamento dos dados.

#### Algumas desvantagens dos sistemas de arquivos

A estrutura dos dados era toda definida dentro da aplicação: **usando recursos como records, structs, etc**.

Era muito complicado implementar mudanças na estrutura dos dados. O programador perdia muito tempo para implementar rotinas de acesso aos dados.

Várias versões dos mesmos dados em arquivos diferentes: **desperdício de espaço e problemas de consistência**.

O programador tinha que se preocupar com a implementação de muitos softwares complexos: **controle de transações, tolerância a falhas, estruturas de indexação, otimização de consultas, etc**.

#### Solução

Para resolver estas limitações, foram desenvolvidos os sistemas gerenciadores de bancos de dados (SGBD).

Um SGBD é uma coleção de programas que permite a criação e o gerenciamento de bancos de dados.

Exemplos de SGDBs

- MySQL;
- PostgreSQL;
- MongoDB;
- Microsoft SQL Server;
- Oracle;
- IBM DB2;

## Vantagens do uso de SGBDs

### SGBDs têm natureza autodescritiva

Um catálogo é fornecido contendo uma série de metadados acerca da estrutura do banco de dados e suas restrições.

**Exemplos de metadados**: as tabelas, as colunas de cada tabela com os seus respectivos tipos, os índices, os procedimentos armazenados, as restrições de integridade, etc.

### Isolamento entre a aplicação e o banco de dados

Todas as tarefas relativas ao gerenciamento dos dados ficam na responsabilidade do SGBD: **o programador pode concentrar os seus esforços no desenvolvimento da aplicação**.

Menor acoplamento entre a aplicação e os dados: **mudanças na estrutura e organização dos dados tem menos impacto na aplicação e vice-versa**.

Maior facilidade para o compartilhamento dos dados: **a estrutura oferecida pelo SGBD pode ser reusada por várias aplicações**.

### Melhor abstração dos dados

Todos os detalhes de armazenamento, indexação e recuperação dos dados ficam na responsabilidade do SGBD. O programador só precisa conhecer informações de alto nível sobre a organização dos dados.

### Suporte a múltiplas visões dos dados

SGBDs oferecem suporte para a definição de múltiplas visões dos dados.

Visões podem ser usadas para controlar quais dados poderão ser acessados por cada grupo de usuário: **e como estes dados serão visualizados**.

### Controle de concorrência

O SGBD gerencia o acesso concorrente quando múltiplos usuários tentam atualizar o banco de dados ao mesmo tempo: **garantindo que o banco de dados permanecerá correto após a execução de todas as atualizações**.

Estas aplicações são chamadas de OLTP (On-line Transaction Processing).

### Verificação de restrições de integridade

O SGBD é responsável por checar as restrições de integridade do banco de dados antes da realização de cada operação.

**Exemplos**: o uso de valores nulos, restrições de unicidade, restrições de chave, referências, etc.

### Controle de redundância

SGBDs permitem que as visões de diferentes grupos de usuários sejam armazenadas em um único local.

Isso reduz a necessidade de redundância dos dados, evitando desperdício de espaço e problemas de consistência.

### Controle de acesso aos dados

SGBDs oferecem ferramentas que nos permitem especificar os usuários que podem acessar o banco: **além de quais recursos eles podem acessar e quais operações eles podem realizar**.

É responsabilidade do SGBD realizar o controle de autenticação e autorização.

### Armazenamento persistente de objetos

SGBDs orientados a objetos realizam o armazenamento e a recuperação de objetos no banco de dados: **fazendo a conversão de objeto para registro e vice-versa. Isto reduz problemas de impedância**.

### Otimização de consultas

O SGBD oferece ferramentas que otimizam o plano de execução de consultas para minimizar o tempo de resposta: **além de índices que aceleram o tempo de resposta das consultas**. Estas ferramentas permitem a resolução de consultas de forma mais eficiente.

### Backup e Recuperação

SGBDs oferecem módulos de recuperação, que permitem que o banco de dados seja revertido para um estado válido após uma falha de hardware ou software.

Módulos de backup permitem o backup dos dados para recuperação após uma eventual falha de disco catastrófica.

### Múltiplas interfaces com o usuário

O SGBD normalmente oferece várias interfaces para o gerenciamento do banco de dados: **interface gráfica, linha de comando, drivers para
acesso via aplicações, etc**.

### Redução no tempo de desenvolvimento de aplicações

Todas as tarefas relativas ao gerenciamento dos dados ficam na responsabilidade do SGBD.

O programador pode focar no desenvolvimento da aplicação.

## Os primeiros SGBDs

Os primeiros SGBDs surgiram mais ou menos na década de 1960.

Os dados eram organizados em arquivos de registros. Os relacionamentos entre os dados eram descritos por meio de ponteiros.

### Modelos de Destaque da Época

**Modelo hierárquico**: os dados eram estruturados por meio de uma árvore.

**Modelo de redes**: representação mais livre, sem a noção de hierarquia.

### Sistemas que tiveram destaque na época

Os SGBDs eram chamados de **bancos de dados navegacionais**: foram utilizados da década de 1960 até meados da década de 1980.

Alguns sistemas de bancos de dados tiveram destaque nessa época:

- O Integrated Data Store (IDS), desenvolvido Charles W. Bachman na General Electric.
- O modelo desenvolvido pelo CODASYL (Committee on Data Systems Languages).
- O Information Management System (IMS), criado pela IBM;

### Problemas dos bancos de dados navegacionais

- Os sistemas eram muito complexos
- Os sistemas exigiam muito tempo de treinamento por parte dos novos usuários
- Dificuldade para expressar consultas

## Modelo Orientado a objetos

Surgiram devido à popularidade do paradigma de programação orientada a objetos nos anos 80.

Incorporação dos principais conceitos deste paradigma à aplicações de bancos de dados: **classes, objetos, métodos, encapsulamento, herança, etc**.

Foram propostos também para resolver o problema de impedância entre a aplicação e o banco de dados.

- Criação do Object Database Management Group (ODMG).
- Criação da Object Query Language (OQL).

Exemplos de SGBDs orientados a objetos:

- Vbase
- O2
- Orion
- Gemstone
- Jasmine
- ObjectStore

Mesmo com as vantagens oferecidas, os SGBDs orientados a objetos não conquistaram muita popularidade.

O modelo o relacional seguiu dominando o mercado de bancos de dados.

## Bancos de Dados Objeto-Relacionais

Depois de um tempo, alguns SGBDs relacionais passaram a dar suporte também ao modelo orientado a objetos.

Permitiam que os usuários aproveitassem as melhores características dos dois modelos: **facilidade de migração de bancos de dados de sistemas legados**.

Exemplos de SGBDs que se tornaram objeto-relacionais:

![ORACLE](https://www.vectorlogo.zone/logos/oracle/oracle-ar21~bgwhite.svg)

Mesmo com o desenvolvimento dos bancos de dados objeto-relacionais, o modelo orientado a objetos não alcançou tanta popularidade.

**Assim, o modelo relacional dominou o mercado de bancos de dados por aproximadamente quarenta anos**.

## Outras Aplicações de Bancos de Dados

Com o passar dos anos, os bancos de dados relacionais evoluíram e começaram a dar suporte ao desenvolvimento de novas aplicações.

Essas novas aplicações permitiam o gerenciamento de dados ainda mais sofisticados.

### Bancos de Dados Multimídia

Um SGBD multimídia oferece estruturas voltadas para o armazenamento e recuperação de dados multimídia, exemplo: **documentos, áudios, fotos e vídeos**.

Oferecimento de tipos de dados, índices e algoritmos especiais para a recuperação desse tipo de informação.

Exemplo de uma consulta resolvida por um banco de dados multimídia:

- Recuperar todas as imagens parecidas com uma determinada imagem.
- Recuperar todos os vídeos com duração maior do que dois minutos.

### Bancos de Dados Espaciais

Um SGBD espacial oferece suporte ao armazenamento e recuperação de dados geoespaciais.

Oferecem o suporte para o desenvolvimento de Sistemas de Informações Geográficas;

Exemplos de consultas que podem ser resolvidas por um banco de dados espacial:

- Recuperar os nomes de todos os rios que passam pelo estado da Paraíba.
- Recuperar todas as unidades de saúde que estão próximas de um determinado local.

### Data Warehouse

Aplicações que processam e analisam dados históricos de grandes bancos de dados para auxiliar gestores em processos de tomadas de decisão.

São usados para a criação de aplicações de Business Intelligence.

Um data warehouse é formado a partir da coleta e agrupamento de dados de múltiplos bancos de dados: **a partir de um processo chamado ETL (ExtractTransform-Load)**.

Exemplos de consultas que podem ser resolvidas por um data warehouse:

- Gerar um relatório mostrando as categorias de produtos mais vendidos em uma determinada filial.
- Gerar um relatório exibindo o lucro de cada filial durante o primeiro mês do ano.
- Gerar um relatório exibindo a evolução do lucro da empresa em um determinado ano.

### Mineração de Dados (Data mining):

Aplicações que buscam encontrar padrões ou tendências em grandes volumes de dados. Também são aplicadas para a realização de análise preditiva dos dados.

São comumente usadas em conjunto com data warehouses.

### Big Data

São aplicações que precisam armazenar, recuperar e processar grandes quantidades de dados em um curto intervalo de tempo.

Surgiram porque, com o tempo, muitas aplicações começaram a gerar uma quantidade enorme de dados.

## A era do Big Data

O surgimento da era do big data foi impulsionado por alguns fatores:

- Grande redução nos custos dos dispositivos de armazenamento de dados.
- A evolução da tecnologia da computação em nuvem.
- Internet das coisas (IoT).
- Desenvolvimento de novos modelos para o processamento de dados distribuídos. Exemplo: **Map Reduce**.
- Desenvolvimento de infraestruturas que implementam esses novos modelos. Exemplo: **Hadoop** e, posteriormente, o **Spark**.
